# 映像セマンティックタグ付けの予備実験

ステータス: 予備実験・PoC段階。MCPツールとしては未公開(server.pyから未参照)。
2026-08-25、実写映像でのエンドツーエンド検証に成功(6節)。

## 目的

media_rendererが「movieを再生する」機能なのに対し、こちらは**movieの中身を理解する**
ための実験。将来的にAI NAS managerが「この動画で何が起きているか説明して」
「野球している動画を探して」のような意味検索・要約に対応するための土台。

検討したいこと: **各映像にどういうタグ付けが必要か**、という設計そのもの。

## 想定パイプライン

1. 単純な映像を用意する
2. 映像をフラグメント(時間区間)に分割する
3. 各フラグメントに意味づけ(タグ付け)する
4. フラグメントのタグ・映像データを連動させ、映像全体のセマンティックを決定する

## 現在の実装(PoC)

- `ai-nas-manager/semantic_fragments.py` — シーン説明文(将来的には映像解析AIが
  生成する想定、現状は人手を想定)から、ルールベースのキーワードマッチングで
  主体・タグ・物語上の役割(opening/activity/closing)を抽出する
  `build_semantic_fragment()`。複数シーンを統合し全体要約を作る`build_digest()`。
- `ai-nas-manager/segment_alignment.py` — 映像断片(`VideoFragment`)・音声断片
  (`AudioFragment`)・意味断片(`SemanticFragment`)を、時間の重なりを根拠に
  対応づける`align_fragments()`。重なり幅の比率を信頼度として付与。
- テスト(`tests/test_segment_alignment.py`, `tests/test_semantic_fragments.py`)は
  いずれも「3人の子供が野球をしている」という単一のサンプルシーンで動作確認。

## サンプル映像データ

`ai-nas-manager/scripts/generate_semantic_sample_media.sh`(ffmpeg依存、要
`apt install ffmpeg fonts-noto-cjk`)で、パイプライン第1段階「単純な映像を用意する」
のためのサンプルを5本生成できる(`ai-nas-manager/media/semantic_samples/`、
gitignore対象・都度再生成する想定)。あえて野球以外のシーンも混ぜているのは、
現状の`semantic_fragments.py`が野球専用に近いハードコードのため、他のシーンで
どこまで汎用的に動くかを検証しやすくするため。

- `sample01_cooking.mp4` — 台所で大人が料理をしている
- `sample02_dog_walk.mp4` — 公園で子供が犬の散歩をしている
- `sample03_reading.mp4` — 子供が静かに絵本を読んでいる
- `sample04_soccer.mp4` — 子供たちが公園でサッカーをしている
- `sample05_baseball.mp4` — 子供たちが公園で野球をしている(既存デモと同系統)

各10秒、H.264+AAC/MP4。シーン説明文を映像内にテキストとして焼き込んでいるだけの
プレースホルダーで、実際の映像認識で生成したものではない
(「既知の制約」参照)。日本語テキストの表示には`fonts-noto-cjk`が必要
(DejaVu等の欧文フォントだと文字化け(豆腐)になる)。

## 6. 実写映像での検証(2026-08-25、成功)

「フレームを1枚1枚解析するのは現実的ではない」という制約のもと、
**平均値法(パワーエレクトロニクスのaverage value modeling)からの類推**で
3段階のパイプラインを設計し、実写映像で検証した。

### 発想の元(平均値法からの類推)

パワーエレクトロニクスのシミュレーションでは、スイッチング周波数を1つ1つ解像せず、
スイッチング周期で平均化することで意味のある低周波の過渡応答だけを取り出す
(average value modeling)。これを映像に当てはめると:
「意味のある変化は、フレームレートよりずっと低頻度で起きる」という前提のもと、
**フレームごとの意味解析を経由せず、安価な信号から直接、区間構造(少数の候補境界)を求め、
意味化(言語化)はその少数の候補にだけ適用する**、という順序になる。
フレームごとに意味vector化してから平均する、という順序では結局全フレームを
処理することになり本末転倒(この誤りを一度やった上での訂正)。

### 3段階パイプライン

1. **安価な境界検出(無意味論)**: ffmpegの組み込みシーン変化検出フィルタ
   (`select='gt(scene,<threshold>)'`)で、全フレームを見ずに候補境界を直接抽出する。
2. **高速タグ付け**: 絞り込まれた少数のfragmentの代表フレームだけを対象に、
   高速に意味づけ(主体・行動・カメラワーク等)する。
3. **高位の意味化**: 各fragmentの意味づけを統合し、映像全体レベルの
   より高次の意味解釈につなげる(`semantic_fragments.py`の`build_digest`と同じ発想)。

### 検証方法・結果

実際のLEGO Mindstorms EV3「Puppy」ロボット紹介映像(実写、48秒、VP9/Vorbis、
1280x720、`C:\Users\yukik\OneDrive\...\LEGO Education EV3 Content\videos\core-models\
MCR-LV-4-3-Puppy.webm`)を使用。

- 段階1: `ffmpeg -i puppy.webm -filter:v "select='gt(scene,0.3)',showinfo" -f null -`
  で候補境界を抽出 → 48秒中9個(2.2/7.1/11.2/23.6/26.2/28.4/33.7/40.9/45.0秒)。
  全フレーム(48秒×30fps≒1440枚)から大幅に削減。
- 段階2: 各候補時刻のフレームを`ffmpeg -ss <t> -i puppy.webm -frames:v 1 <out>.png`
  で抽出し、Claudeが実際に見て言語化。9個中8個が実際に意味のある変化
  (カメラのカット、人の手の介入、ロボットの姿勢変化)に対応していた。
  1個(11.2秒)は7.1秒とほぼ同一内容で、閾値0.3では検出しすぎの可能性がある
  (誤検出/冗長検出の実例として記録)。
- 段階3: 8つのfragmentの意味づけ(引き画/クローズアップ、ロボット/手、
  静止/操作/姿勢変化)を統合し、「ロボット全体を見せる→パーツ操作→
  表情のクローズアップ(2回)→姿勢変化、という編集されたカット構成を持つ
  製品デモ映像」という映像全体レベルの意味解釈を生成できた。

**これが求めていた「映像tag」の最終形**(ユーザー確認済み、2026-08-25)。

### この検証で分かったこと・残る課題

- 実写・実サイズの映像で、意味のある区切りをほぼ正しく少数に絞り込めることを確認できた
  (誤検出率: 検証した9候補中1個)。
- 閾値(今回は0.3)の妥当性は映像の性質に依存する。誤検出(11.2秒)の扱い
  (後段の意味づけで重複と判断し統合する、閾値を上げる、等)は未検討。
- 段階2「代表フレームの言語化」は今回Claudeが手動で行ったが、`semantic_fragments.py`の
  野球専用ハードコードでは全く対応できない(このロボット映像は野球と無関係)。
  段階2をどう自動化・汎用化するかが次の課題。
- 段階3の統合ロジックも今回は手動で行った。`build_digest`の単純な
  タグ集計+テンプレート文とは異なり、実際には「カメラワークの変化」
  「時系列上の因果関係」まで踏まえた統合が必要だった。
